# Phishing Analysis Tools

---

## 1 - Identifying Artifacts

When analyzing a suspicious or malicious email, your first goal is to collect key artifacts that can help determine its legitimacy and intent. These artifacts provide the foundation for deeper investigation, such as reputation checks, threat intelligence lookups, and behavioral analysis.

## **Header Artifacts**

When you begin your analysis with the email header, you should take note of the following points:

- **Sender email address:** Where did the email originate from?
- **Sender IP address:** What is the source IP, and what does a reverse lookup reveal?
- **Email subject line:** Does it contain urgency or a call to action?
- **Recipient email address:** Who is the intended recipient (To/CC/BCC)?
- **Reply-To email address:** Where are responses being directed?
- **Date and time:** When was the email sent?

## **Body Analysis**

Next comes the email body, which has its own set of artifacts to be aware of:

- **URLs and hyperlinks:** Identify all links and expand shortened URLs to reveal their true destination
- **Attachment name(s):** What files are included, and do their names or extensions appear suspicious
- **Attachment hash:** Generate a hash value for threat intelligence lookups

## Mail Body Analysis

Determining the destination of a link within an email can be as easy as right-clicking the link and selecting `Copy link address` (the option's name may vary depending on your browser or email provider). From here, you can safely assess the URL without actually following it to the destination page.

Another effective way to identify URLs in an email is to use a [URL extraction tool(opens in new tab)](https://www.convertcsv.com/url-extractor.htm). These tools let you paste raw email content and automatically parse all embedded links, saving time and reducing the risk of missing hidden or obfuscated URLs. Tools like [CyberChef(opens in new tab)](https://gchq.github.io/CyberChef/#recipe=Extract_URLs(false,false,false)) can also perform this function, making them a versatile option for email analysis.

[VirusTotal(opens in new tab)](https://www.virustotal.com/gui/) is a widely used tool that allows analysts to check the reputation of files, URLs, IP addresses, and domains using data from dozens of security vendors. By submitting a file or indicator, you can quickly determine whether it has been flagged as malicious and review detailed detection results. VirusTotal also allows users to upload files and submit URLs for analysis, making it a powerful resource for investigating suspicious artifacts.

## Malware Sandboxes

**ANYRUN**

[ANY.RUN(opens in new tab)](https://app.any.run/) is an interactive malware sandbox that allows analysts to safely execute and observe suspicious files and URLs in real time. Unlike traditional sandboxes, it provides a hands-on experience in which you can interact with the environment, monitor processes, view network activity, and analyze system changes as they happen. This makes it a powerful tool for understanding how malware behaves and identifying key indicators of compromise in a controlled setting.

**Hybrid Analysis**

Similar to the tool above, [Hybrid Analysis(opens in new tab)](https://hybrid-analysis.com/) is a free malware analysis sandbox that allows analysts to upload and examine suspicious files in a controlled environment. It provides detailed insights into file behavior, including system changes, network activity, and indicators of compromise, helping analysts better understand the potential impact of a malicious file.

**JOESandbox**

JOESecurity created the [JOESandbox(opens in new tab)](https://www.joesandbox.com/) for advanced malware analysis. It performs both static and dynamic analysis on suspicious files and URLs. It generates comprehensive reports that highlight behavior, indicators of compromise, and threat classifications.

## Using PhishTool

A powerful platform that streamlines phishing investigations is [PhishTool(opens in new tab)](https://www.phishtool.com/). It is designed for security professionals across multiple disciplines. PhishTool automates much of the manual work involved in analyzing suspicious emails

PhishTool brings everything together in one place. By combining threat intelligence, OSINT, email metadata, and automated analysis workflows, PhishTool provides a centralized view of phishing activity, helping you quickly identify malicious intent and extract valuable indicators of compromise.

One of PhishTool’s standout features is its integration with VirusTotal, allowing you to view reputation and detection results without leaving the tool. This seamless integration helps speed up investigations by bringing external intelligence directly into your workflow.

# Phishing Analysis Tool — Lab Takeaways

## 1. The goal of phishing triage

The lab is training you to answer:

> **Who sent it? → What is it trying to do? → What infrastructure is involved? → Is it malicious? → What IOCs can I hunt/block?**
> 

A suspicious email should be treated as a collection of **artifacts**, not just something that “looks suspicious.”

---

## 2. First: identify the impersonation

Look for:

- Brand/company being impersonated
- Spoofed domains
- Look-alike domains
- Suspicious sender names
- Subject suggesting urgency/account problems/payment issues

### Example

`capitai-one.com` → visually resembles `capitalone.com`

**Analyst mindset:**

Don't trust the displayed brand. Compare the **actual domain** with the legitimate organization's domain.

---

## 3. Header analysis — what matters

Use the **raw email header**, not just what the mail client displays.

Extract:

| Artifact | Why it matters |
| --- | --- |
| From | Who appears to have sent it |
| Return-Path | Helps identify the actual sending/envelope address |
| Reply-To | Can reveal where replies are redirected |
| Originating IP | Useful for infrastructure investigation |
| Received headers | Reconstruct mail-server path |
| Date/time | Establish timeline |
| To / CC / BCC | Identify targeted recipients |

### Important mindset

**From ≠ necessarily the real sender.**

A phishing email can manipulate the visible sender while the raw headers reveal a different infrastructure path.

---

## 4. URL analysis

**Never click the link just to see where it goes.**

Instead:

1. Right-click → **Copy Link Location**
2. Extract the complete URL
3. Identify the **root domain**
4. Check reputation / infrastructure
5. Defang it when reporting

Example:

```
https://etekno.xyz/login
        ↓
Root domain: etekno.xyz
        ↓
Report as: etekno[.]xyz
```

For shortened URLs:

```
https://t.co/yuxfZm8KPg?amp==1
```

preserve the **full URL**, because the shortening service itself can be an important artifact.

### Tools

- CyberChef → extraction / defanging
- URL Extractor → extract URLs
- URLScan → investigate URLs safely
- VirusTotal → reputation/context

**Key lesson:** A URL being shortened does not make it safe.

---

## 5. Attachment analysis

Never open a suspicious attachment directly on your normal machine.

Collect:

- Filename
- File type
- SHA256
- Extracted strings
- Processes
- Network connections
- Domains/IPs
- Exploited vulnerabilities

Example:

```
Payment-updateid.pdf
SHA256:
cc6f1a04...
```

The **SHA256 becomes a pivot**:

```
Hash
 ↓
VirusTotal / sandbox
 ↓
Known detections
 ↓
Related files / domains / IPs
```

---

## 6. Sandbox analysis — what should you look for?

The lab's Any.Run cases are particularly important for your SOC mindset.

Don't just look at:

> "Malicious"
> 

Look deeper into **why**.

### Extract:

**File**

- Filename
- SHA256
- File type

**Network**

- Malicious IPs
- Malicious domains
- URLs
- Connections made by processes

**Execution**

- Processes created
- Suspicious processes
- Child processes
- Downloads
- Persistence attempts

**Exploitation**

- CVE being exploited

Example from the lab:

```
Excel attachment
      ↓
Execution
      ↓
Office vulnerability
      ↓
CVE-2017-11882
      ↓
Network connections
      ↓
Malicious domains/IPs
```

That is much more valuable than simply recording **"malicious Excel file."**

---

## 7. Process ≠ automatically malicious

One important lesson from the `svchost.exe` example:

> **Context matters.**
> 

`svchost.exe` is a legitimate Windows process, but the sandbox flagged it because of **the network behavior associated with it**.

So don't think:

```
svchost.exe = malware
```

Think:

```
svchost.exe
+ suspicious execution context
+ suspicious network connection
+ malicious destination
= investigate
```

This is exactly the kind of reasoning you need as a SOC analyst.

---

## 8. Defanging = safe IOC handling

When sharing IOCs with analysts:

### IP

```
209.85.167.226
↓
209[.]85[.]167[.]226
```

### Domain

```
etekno.xyz
↓
etekno[.]xyz
```

### URL

```
https://example.com/login
↓
hxxps://example[.]com/login
```

Purpose:

> Prevent someone from accidentally clicking/opening the IOC while still allowing analysts to read and search it.
>

# The SAL1 mindset to take from this lab

When you receive a suspicious email, mentally run:

```
EMAIL
 │
 ├── Sender
 │    ├── From
 │    ├── Return-Path
 │    ├── Reply-To
 │    └── Originating IP
 │
 ├── Header
 │    └── Mail path / anomalies
 │
 ├── Body
 │    ├── URLs
 │    ├── Urgency / social engineering
 │    └── Impersonated brand
 │
 ├── Attachments
 │    ├── Filename
 │    ├── SHA256
 │    └── File type
 │
 └── Enrichment
      ├── VirusTotal
      ├── URLScan
      ├── Any.Run
      └── PhishTool
             ↓
          IOCs
             ↓
     Hunt / Block / Escalate
```

### Most important takeaway

**Don't stop at "Is this phishing?"**

Train yourself to ask:

> **What evidence proves it? What artifacts can I extract? What infrastructure is connected to it? What else should I search for in the environment?**
